# RostiQ

RostiQ is a team planner by [Caersultancy](https://www.caersultancy.com) for sports teams:
availability, calendar, carpool and WhatsApp sharing — one app, one login, many teams.

**Live:** https://rostiq.be/

## How it is organised

```
RostiQ (one site, one login, one Firebase Realtime Database)
├─ teams/<teamId>/        everything of one team
│  ├─ info               name, logo, colours, season, admin name (readable by anyone signed in)
│  ├─ admins/<uid>       team admins
│  ├─ members/<uid>      linked accounts → player id
│  ├─ players, schedule, matches, carpool, settings, requests
└─ users/<uid>/
   ├─ teams               "my teams" index
   └─ profile             my phone, email, federation number, home town (shared by all my teams)
```

- **RostiQ admin** (`PLATFORM_ADMINS` in `team.js` and `tools/build_rules.py`): creates teams on
  `rostiq.html` and can manage every team; hands out pilot codes and can open self-service to everyone.
- **Self-service** (`start.html`): a signed-in person (verified email) starts a team with a pilot code
  (`signupCodes/<CODE>/uses`) or without one when `signup/open` is true. One write creates the team with them
  as its only admin and first player; max 3 self-started teams per person (`users/<uid>/created/s1…s3`).
- **Team admins**: manage one team (players, matches, settings, access requests). The RostiQ admin
  makes someone team admin on that team's Admin tab.
- **Players** open the team link (`…/rostiq/?t=<teamId>`), sign in, send an access request and get
  in once a team admin approves. Someone in several teams picks a team after signing in, and can
  switch with "⇄ Switch team".

Pages: `index.html` (availability), `carpool.html`, `ploeg.html` (team), `admin.html` (team admin),
`rostiq.html` (RostiQ admin).
All texts are in `i18n.js` (NL/EN/FR); the default follows the browser language, switchable in the menu.

## Personal details across teams

Phone, email, federation number and home town belong to the person, not the team. They are kept once
per account in `users/<uid>/profile` (only readable by that person) and copied into the player row of
each team, where teammates see them. Changing them in one team updates the profile and the other teams;
an admin's correction in one team wins and spreads to the other teams at the player's next visit;
opening a team copies the profile into that team's row; an access request carries the profile, so
the admin's approval fills it in at once. The name stays per team.

## Database rules

Generated by `python tools/build_rules.py`:

- `database.rules.json` — the rules for this structure.
- `database.rules.transition.json` — the same plus the old single-team (Pampas) structure at the
  database root, for the switch-over period only.

They were tested against the Firebase Realtime Database emulator (197 cases: strangers, members,
team admins, RostiQ admin, isolation between teams, approval flow, branding, profiles, migration,
last seen, account deletion, error reports).

## Landing page

`home.html` is the public landing page (NL/FR/EN, no sign-in, no database). `index.html` sends a visitor there
only when there is no team link (`?t=`), no `?pick`, no team remembered on the device and no sign-in in
progress (email link or Google redirect); everyone else goes straight to the app.

## Privacy and error reports

`privacy.html` holds the privacy statement (NL/EN/FR, readable without signing in) and, when signed in,
**Download my data** (one JSON file) and **Delete my account**: one atomic write removes the player row,
carpools, membership, admin role, last-seen, profile and feedback of that account in all its teams, then
the Firebase login itself (which needs a sign-in from the last few minutes). The only admin of a team with
other members must first make someone else admin (team admins can do that on the Admin page).

The app's own JavaScript errors are collected on the device and sent to `errors/` (no uid or name, at most
one report per minute); the RostiQ page shows them grouped, with a count.

## Last seen (admins only)

Each member's app stamps `lastSeen/<team>/<uid>` with the server's clock (at most every 10 minutes).
It lives outside the team on purpose: members can read their whole team, but only that team's admins
and the RostiQ admin can read `lastSeen/<team>`. A member can only write their own entry, and only
with the server time. Admin → Spelers shows "Last seen …" per player and an "Active this week" tile.

## Moving Pampas from the old site (done)

Pampas was moved from the old single-team site with the transition rules and a one-off
`migrate.html` (see git history). That page was removed afterwards: under the final rules it can't
read the old data any more, so running it again would overwrite Pampas with an empty team.

## Branding

Team admins set their team's name, logo and colours on **Admin → Branding** (live preview, then
save). The logo is scaled down in the browser and stored inline in `teams/<id>/info/logo`; the
colours are two picks (header + highlight) from which a full light and dark palette is generated
(`makePalette` in `common.js`). The database rules only accept `#rrggbb` colours and PNG/JPEG/WebP
images (or a file in `assets/`, like Pampas' wordmark).

RostiQ's own look follows the preferred brand package in `assets/brand/` (gradient R mark + "RostiQ"
wordmark; deep indigo `#1E1B4B`, electric cyan `#00D4FF`, soft violet `#8B7CFF`, near black `#0B0D14`,
off white `#F6F7FA`; font Inter) and is the default for every team without its own colours. A team can also choose classic serif headings
(`info/font = "serif"`, as Pampas does).

`python tools/make_brand.py` regenerates the RostiQ mark, app icons and link preview.
