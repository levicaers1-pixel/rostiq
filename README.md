# Rostiq

Rostiq is a team planner by [Caersultancy](https://www.caersultancy.com) for sports teams:
availability, calendar, carpool and WhatsApp sharing — one app, one login, many teams.

**Live:** https://levicaers1-pixel.github.io/rostiq/

## How it is organised

```
Rostiq (one site, one login, one Firebase Realtime Database)
├─ teams/<teamId>/        everything of one team
│  ├─ info               name, logo, colours, season, admin name (readable by anyone signed in)
│  ├─ admins/<uid>       team admins
│  ├─ members/<uid>      linked accounts → player id
│  ├─ players, schedule, matches, carpool, settings, requests
└─ users/<uid>/teams      "my teams" index
```

- **Rostiq admin** (`PLATFORM_ADMINS` in `team.js` and `tools/build_rules.py`): creates teams on
  `rostiq.html` and can manage every team.
- **Team admins**: manage one team (players, matches, settings, access requests). The Rostiq admin
  makes someone team admin on that team's Admin tab.
- **Players** open the team link (`…/rostiq/?t=<teamId>`), sign in, send an access request and get
  in once a team admin approves. Someone in several teams picks a team after signing in, and can
  switch with "⇄ Switch team".

Pages: `index.html` (availability), `carpool.html`, `ploeg.html` (team), `admin.html` (team admin),
`rostiq.html` (Rostiq admin), `migrate.html` (one-off move of the old single-team Pampas data).
All texts are in `i18n.js` (NL/EN).

## Database rules

Generated by `python tools/build_rules.py`:

- `database.rules.json` — the rules for this structure.
- `database.rules.transition.json` — the same plus the old single-team (Pampas) structure at the
  database root, for the switch-over period only.

They were tested against the Firebase Realtime Database emulator (62 cases: strangers, members,
team admins, Rostiq admin, isolation between teams, approval flow, migration).

## Moving Pampas from the old site

1. Publish `database.rules.transition.json` (old site and Rostiq work side by side).
2. As Rostiq admin open `migrate.html`: downloads a backup and copies Pampas to
   `teams/pampas-wintermidam` (re-runnable; the old data stays as a safety net).
3. Check Pampas in Rostiq; then the old address becomes a redirect to Rostiq.
4. Publish `database.rules.json` (removes the old structure and its whole-database read rule).

## Branding

`python tools/make_brand.py` regenerates the Rostiq icons and link preview. A team's own logo
(e.g. `assets/wordmark-light.png` for Pampas) and colours are set in `teams/<id>/info`.
